# Watermarking v2 — model-level identity, the provenance index, and fingerprints

Status: **implemented 2026-08-20** (operator decisions recorded; spec
adversarially reviewed — 10 findings folded in; Phase 0 measured, two
amendments applied (§0); phases 1–5 built same day, each review-passed.
Outstanding: the Wwise-conversion leg of phase 0 waits for the Wwise
MCP — Vorbis, Wwise's music codec, already passes).
Supersedes the per-output allocation scheme described in
`khaos_attribution/watermark.py`'s docstring; the codec and embedding
machinery there are retained. Implementation lands as one contract bump
(**0.10.0 → 0.11.0**) with the usual uv.lock checklist across consumers.

## 0. Phase-0 measurements and the two amendments they forced

Measured on real generated outputs (scripts/watermark_survival.py,
2026-08-20, laptop):

- **Codecs are safe**: MP3 128/320k, AAC 128k, Opus 96k, Vorbis q4
  (Wwise's music codec), 44.1k resample — detection prob ≥ 0.997 and the
  ID decodes correctly (SECDED correcting ≤1 bit as designed).
- **Mid-file excerpts break the MESSAGE, not the presence**: a 10 s
  excerpt from anywhere past the start decodes with 3–4 flipped bits at
  detection prob ≈ 1.0. No affordable code fixes 3–4 errors in 16 bits
  (t=2 would not help — the 2048/1-bit decision stands, now for a better
  reason), and windowed majority voting does not rescue it (windows
  disagree with each other). This weakness exists in the CURRENT
  per-output scheme too; phase 0 merely measured it.
- **Double-embedding corrupts**: embedding a second AudioSeal message
  over an already-marked file yields garbage decodes for BOTH messages.

Amendments:

1. **The re-embed migration is cancelled** (supersedes the §7 decision it
   was built on — the operator chose re-embed before this was measurable).
   Legacy outputs keep their per-output IDs; `legacy_ids` resolves them
   forever. The provenance sidecar schema needs no change at all.
2. **Content-corroborated identity** (revised after live measurement
   2026-08-20): windowed-agreement gating turned out NOT to discriminate
   — mid-file windows misdecode even on full files, and an excerpt's
   miscorrection is deterministic (its own windows agree on the same
   wrong codeword). The working rule: /verify matches CONTENT first; a
   fingerprint match names the exact output and its run, and the decoded
   payload is reported as corroboration — confirmed, contradicted
   ("didn't survive this copy"), or absent. Only when no content match
   exists does the raw decoded ID resolve alone (full foreign-machine
   files decode correctly; the residual risk — an excerpt of unindexed
   audio miscorrecting onto an allocated model ID — is ~models/2048 and
   the wording stays match-based).

## 1. Threat model (decided)

The watermark is **honest-actor provenance, not DRM**. It is designed to
survive the transforms of normal distribution — lossy codecs, game-engine
media conversion (Wwise), trimming, loudness normalisation — and to make
AI-made audio *identifiable*, not *uncopyable*. Determined adversaries can
strip any open post-hoc watermark; the answer to a stripped mark is the
fingerprint layer (§5), which identifies content rather than payload.
/verify's public wording states this plainly.

## 2. What the watermark identifies (decided)

**One ID per training run** (adapter version). All audio generated by a
run — Platform outputs, Workshop auditions, repaint/extend/cover
derivatives, and exported stems — carries the run's ID. A retrain is a new
model and a new ID. The identity question a found-in-the-wild file answers
from audio alone is the legal one: *which model, whose consent, which
rights catalogue*. Exact-output identity moves to the fingerprint layer.

Scheme: **AudioSeal, unchanged** (decided): 16-bit payload carrying the
existing extended-Hamming (16,11) SECDED codeword — **2048 usable
payloads, 1-bit correction** (operator chose ID headroom over stronger
correction). Phase 0 (§0) validated this for whole files and codecs and
showed excerpt decode fails at ANY affordable code strength — the
consistency gate + fingerprints answer excerpts, not more ECC.

**One number system (review finding 2).** `watermark_id` everywhere — in
model cards, sidecars, the index, and /verify responses — is the 16-bit
**codeword**, exactly as the current contract defines it ("the ID embedded
in the audio IS the watermark_id in the record"). Allocation picks a
*payload* (0–2047) and immediately encodes it; the payload never appears
in any stored record. Schema ranges stay 0–65535 with the validity rule
"decodes to a valid payload".

## 3. Allocation (replaces the per-output registries)

- The ID is allocated **once, at training completion**, by the Workshop,
  and stamped into the run's **model card** (`watermark_id`, the
  codeword). The card travels with the adapter, so every serving machine
  learns the ID by reading the card — no per-output allocation, no
  sidecar scans, no exhaustion at generation time.
- **Machine bands** partition the payload space (three training machines,
  no coordination needed, survives offline training):

  | band | payloads |
  |---|---|
  | reserved (calibration, migration tooling) | 0–31 |
  | laptop (M2 Max) | 32–703 |
  | studio (M4 Max) | 704–1375 |
  | threadripper | 1376–2047 |

  672 payloads per machine; at real training rates (a handful of runs a
  month) that is decades. Band selection via the existing machine profile
  with a `KHAOS_WM_BAND` override. **Eligibility:** only runs that
  complete and export an adapter allocate; the smoke test's synthetic
  runs never allocate (they are never served). **Exhaustion:** training
  completion fails LOUDLY with a clear message — no silent unmarked
  adapters. **No automatic reclamation** — an ID once embedded anywhere
  is spent; manual reclamation only via the frozen legacy list below.
- **Legacy exclusion (review finding 1).** Per-output IDs were issued
  from this same space (Platform ledger + audition sidecars on three
  machines). At migration time, every ever-issued legacy payload is
  collected into a **frozen canonical file**
  (`legacy_watermark_ids.json`, shipped in the contract package data) and
  those payloads are **permanently excluded from run allocation** — no ID
  is ever owned by both a legacy output and a run. `watermark_issuer()`
  is retired from v2 semantics; it survives only to interpret IDs found
  in the frozen legacy list.
- The old platform/app **issuer partition is retired** (identity belongs
  to the model, which both apps share).
- Backfill (decided): the served adapters get IDs allocated and written
  into their model cards at migration time, so /verify answers for every
  model already in use.
- **A card without a watermark_id** (pre-backfill, or synced from a
  machine that has not migrated) — review finding 6: the Workshop refuses
  to *complete a new training run* without allocating (fail loud); at
  *generation* time the existing degrade path holds — generate, warn
  loudly, record `watermark_id: null` in the sidecar — because refusing
  to serve music over a missing serving aid punishes the listener for an
  operator's sync backlog. The Engine Room's coverage view (§4) makes the
  backlog visible instead of silent.

## 4. The provenance index (the "database")

A **derived, rebuildable SQLite index — never a source of truth**. The
canonical records remain plain files that sync between machines by
filesystem handoff: provenance sidecars (pinned), model cards,
`rights.json`, `attribution.json`, **and tombstone records (§6)** — the
index is rebuilt by scanning them, with the pipeline's cache discipline
(schema version + source mtimes compared on open; mismatch → rebuild).

Lives Platform-side (it serves /verify). The Engine Room may **read** it
for diagnostics (index health, staleness, coverage — including "adapters
without watermark identity") — it never writes (decided).

| table | maps | built from |
|---|---|---|
| `models` | watermark_id → run_id, artist_id, adapter_hash, consent snapshot, card path | model cards (both homes) |
| `outputs` | generation_id → model, audio path, sidecar path, created_at | provenance sidecars (Platform outputs + Workshop auditions) |
| `legacy_ids` | legacy watermark_id → generation_id | the frozen legacy list + a sidecar scan (sidecars keep their original `watermark_id`) |
| `fingerprints` | landmark hash → generation_id, offset | stored audio (mixes + stems) |
| `tombstones` | content hash + fingerprints of deleted outputs → model, deleted_at | tombstone record files (§6) — canonical, so the table IS rebuildable |

Track rights are **not copied** into the index; `rights.json` stays the
single home. The index stores paths/keys to reach them.

**Concurrency and cost (review finding 10).** The builder is incremental
(mtime cursor), reads only atomically-written files, and skips torn ones
(they surface on the next pass — same tolerance the registry already
has). Fingerprinting runs as a queued post-generation step, never a bulk
scan on the serving hot path. /verify never blocks on a rebuild: it reads
the current index and, when the cursor lags the newest sidecar, says so —
"exact-output matching is catching up" — rather than answering UNKNOWN
silently.

## 5. The fingerprint layer (decided: full mixes + stems)

Closed-set matching against a corpus held in pristine form — the
watermark narrows any query to one model's outputs first, so the search
space is hundreds, not millions.

- **Landmark (constellation) fingerprints** are the index: robust to
  re-encoding, excerpting, noise; discriminates near-identical takes
  (seed variations), which CLAP cannot be trusted to do.
- **Cross-correlation against the stored WAV** confirms any claimed match.
- CLAP embeddings (already computed for attribution) may serve as an
  optional coarse pre-filter; never as the final word.
- Stems are fingerprinted as well as mixes (decided).

## 6. /verify behaviour (decided)

Two layers, answered in order:

1. **Watermark decode** → `models` first, then `legacy_ids` (the frozen
   exclusion in §3 guarantees an ID is in at most one) → model card:
   artist, consent, training catalogue and its rights.
   *Decoded ID with no local card* (not-yet-synced adapter): say exactly
   that — "KHAOS watermark confirmed; this machine does not have the
   model's card yet (sync adapters)" — never a guess, never a bare
   failure.
2. **Fingerprint** within that model's outputs → exact generation, its
   attribution estimate and per-track influence splits.

**No watermark detected** → fingerprint-only identification is permitted,
worded as a **match with confidence**, never as definitive: *"No watermark
detected, but this audio matches output X of model Y (98% match)."*

**Deleted outputs** (decided: tombstone; canonical-file form per review
finding 4): deletion removes audio and sidecar and writes a **tombstone
record file** — `outputs/<artist>/.tombstones/<generation_id>.json`
(content hash, fingerprint set, model, deleted_at; no audio) — which
syncs across machines like every other canonical file and from which the
index derives. The delete confirmation in both apps must say what delete
now means: the audio goes; the fact it existed is kept so it can still be
identified in the wild.

**Wording** (decided: artist-led):

```
✓ KHAOS watermark detected

Made with the Port Sulphur Band adapter
Trained with the artist's consent · rights on file

Adapter run: run_20260806_220058 (6 Aug 2026)
Exact output: matched — generation f3a1… (99.2%)
```

## 7. Migration (amended by §0: NO re-embedding)

Measured double-embed corruption cancels the re-embed plan. Instead:

- Existing outputs (Platform and Workshop auditions) keep their
  per-output IDs untouched — audio and sidecars are not modified at all.
- The frozen legacy list (§3) plus a sidecar scan builds `legacy_ids`,
  so every legacy ID resolves to its exact output permanently.
- The served adapters' model cards are backfilled with run IDs (§3);
  only audio generated AFTER phase 4 carries them.
- **Sequencing across machines** (review finding 5): the 0.11.0 pin bump
  deploys on all three machines before any card backfill writes the new
  field. The 0.11.0 model-card schema accepts both versions
  (`schema_version` enumerates 1.0.0 and 1.1.0; `watermark_id` optional)
  so a backfilled card syncing to a not-yet-bumped machine is the only
  forbidden state — bump first, backfill second.

## 8. Contract changes in khaos-attribution 0.11.0 (one bump, decided)

1. `model_card.schema.json`: `watermark_id` (codeword, 0–65535, must
   decode to a valid payload; required for new cards, optional for
   pre-v2 cards).
2. Provenance sidecar schema: **unchanged** (§0 amendment 1 — no
   migration fields needed).
3. Tombstone record schema (new).
4. `watermark.py`: `allocate_model_watermark_id(band, used)` honouring
   the frozen legacy exclusion; `decode_consistent()` — the
   consistency-gated decode of §0 amendment 2; per-output
   `allocate_watermark_id` deprecated (decode/issuer retained for the
   legacy list only).
5. `legacy_watermark_ids.json` frozen list shipped as package data.
6. Provenance-index schema doc (DDL + rebuild/staleness/concurrency
   rules) and fingerprint format doc.
7. Consumers (Workshop, Platform) bump pins + uv.lock together.

Implementation notes: /verify also stands WITHOUT the watermarker —
content matching answers alone; the index lives at
`outputs/provenance_index.sqlite3`, one background fingerprint worker,
WAL mode.

The old /verify resolves per-output IDs and returns the **first matching
sidecar** — under shared run IDs that is live misattribution, which is
why phase 3 strictly precedes phase 4.

Each phase lands with the standing sign-off ritual (scar check, review,
audit) and suites green in every touched repo.
